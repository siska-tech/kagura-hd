# デグリッチ RC1向け省資源PCMストリーミング検討

2026-11-07。実装前の設計提案。対象は `releases/queue8-qspi-deglitch-rc1/build-inputs/` の固定入力であり、作業ツリーのRTLや旧Queue8のSTA値を基準にしない。

## 結論

**PSRAM上の固定長A/Bバッファと既存PCM先読みFIFOを再利用し、半面の所有権と補充完了通知だけを追加する方式**を推奨する。初版は48 kHz signed8、monoまたは左右専用の2chに限定する。可変レート、16 bit化、圧縮デコーダ、大きなFPGA内FIFO、任意長ディスクリプタキューは追加しない。

RC1そのもののbitstreamにはストリーミング用の所有権APIがない。安全な連続補充には派生RTLとHost API拡張が必要。RC1を変更せず、時刻を頼りにループ領域を書き換える方法は採用しない。

## 確認できた制約

- [RC1 manifest](../releases/queue8-qspi-deglitch-rc1/manifest.json): CLS 4212/4320（空き108、2.5%）、BSRAM 23/26、Setup +0.659 ns、Hold +0.527 ns。タイミングの余裕があっても追加論理の収容を保証しない。
- 固定入力の `rtl/fb/kagura_fb_core.sv` は `BUFFER_ADDR_BITS=5`。先読みは32 byte/ch、48 kHzでは約0.667 ms分であり、Host転送待ちの吸収には小さい。
- `rtl/audio/kagura_pcm_prefetch.sv` は共通の未応答要求1件を持ち、要求受理時にアドレスを進め、成功応答時にFIFOへ格納する。補充可能の判定は要求発行時や再生時刻ではなく、当該半面の最終成功応答を基準にできる。
- `rtl/fb/kagura_fb_pcm_port.sv` の32 bitキャッシュは2chで共用。左右交互の要求ではヒットを期待できず、さらにHost書込み完了でflushされる。96 kB/sの音声payloadだけをPSRAM実負荷と見なせない。
- 現行STOPは再生停止であり、prefetchのconfiguredを消去しない。ストリーム停止に必要な所有権回収・要求抑止は別途設計する。
- [既存監査](pcm-double-buffer-sta-audit.md)の方向性を継承するが、そこにある旧Queue8のCLS 4246・Setup +0.050 nsは今回の基準ではない。

## 最小構成案

半面を4096 byteに固定し、各chに8192 byteの連続した領域を割り当てる。STARTは8192 byte境界、END=START+8192、LOOP=STARTとする。FB・診断領域と重ならず、表現可能なENDを持つ位置をHostが確保する。半面境界はアドレス下位12 bit、A/Bはbit12から判定でき、新たな22 bitの中点レジスタや任意長比較器を避けられる。範囲検査は停止時のみ行う。

音声本体はPSRAMに16 KiB（ステレオ）または8 KiB（mono）。FPGAの既存32 byte/ch FIFOは維持し、追加BSRAM **0**を目標にする。Hostはファイル等から64～512 byte単位で読み出して既存WRITEへ分割でき、曲全体や16 KiBをRAMへ複製する必要はない。非同期DMAを使用する場合は完了まで転送元バッファを保持する。

各半面は「Host所有／充填公開済み／FPGA読出し中」の状態を持つ。公開済みへの遷移はHostが全WRITEの成功完了を回収した後だけ許す。FPGAは次の半面が未公開なら要求を止め、古い周回のデータを再生しない。最終byteの要求に半面終端を記録し、その成功応答をFIFOへ格納した時点でHostへ返す。エラー・破棄応答を正常返却として扱わない。

初版のステレオは左右を一組として扱い、左右双方が返却されてから補充可能にし、双方のWRITE成功後に1回の公開操作でreadyにする。独立した左右の開始・停止・半面サイズは扱わない。monoでは参加chを停止時に選択する。これによりAPIと世代管理を共通化するが、要求ゲートは各chに必要。

補充状態は読み出しても消えない状態値とする。世代付きの返却tokenをHostが読み、そのtokenと一致する公開だけを受け入れる。同じtokenの再公開は無作用、古いtokenは拒否する。token幅と折返し条件はABI確定前に決める。1 bitのA/B反転だけでは停止・再開後の古い要求を判別できない。複数byteのtokenを使う場合はsnapshot読出しと最終byteでの原子的な公開が必要で、その資源も計上する。

新しい状態・公開CSRは既存INDEX/DATA経路へ小さく追加する候補とする。アドレスは未割当を確認後に確定し、ABI版と機能識別を追加する。既存CAPSはFFなので空きbitを仮定しない。従来モードは既定で維持する。補充通知を音声設定snapshotやHDMI側CDCへ載せず、system54内で完結させる。

STOP・再PREPARE時にはstream要求を先に抑止し、未応答を回収または破棄した後、FIFOと所有権を初期化して新しいセッションを開始する。Hostも古いWRITEをdrainしてから再開する。単なるENABLE解除と所有権を破棄するSTOPを区別する。既存PCM制御への接続はこの違いを検証する必要がある。

## 補充量と期限

|半面/ch|ステレオPSRAM|半面の音声時間|用途|
|---|---:|---:|---|
|2048 byte|8 KiB|42.67 ms|将来の省PSRAM候補。初版では選択機能を付けない|
|4096 byte|16 KiB|85.33 ms|推奨初期値|
|8192 byte|32 KiB|170.67 ms|長いHost停止への余裕が必要な場合の別ビルド候補|

ステレオの平均payloadは96000 byte/s。QSPI 5 MHzの理論payload上限2.5 MB/sに対して3.84%だが、命令・状態読出し・ACK待ち・PSRAM仲裁・描画競合を含まない下限である。4096 byte半面では左右8192 byteを補充し、64 byte WRITEなら128命令、平均1500 WRITE/sとなる。Queue8はその完了回収に再利用し、音声専用の新しい転送キューをFPGAへ追加しない。

85.33 msを保証された補充猶予としない。実際の期限は「左右返却をHostが知ってから、どちらかのchが次周の当該半面を要求するまで」。先読み量、左右の返却差、ポーリング遅延、公開処理を差し引く。32 byte先読みは約0.667 msの目安だが、これだけを引いた値も保証値ではない。

Hostは補充を描画より優先し、補充中に長いFILL/COPY/PRESENT待ちを前方へ積まない。Queueが満杯になってから優先度を変えても実行中・先行命令は追い越せないため、描画の投入量と最大実行時間を制限する。初期評価の目標は、返却認識から左右公開まで40 ms以下。これは設計目標であり実測値ではない。SDカードやネットワークなど供給元の停止時間も含めて測り、必要ならHost側に小さな先行読出しバッファを置く。

未補充でFIFOが枯れた場合はsticky underrunを記録し、ステレオ双方を停止・無音化して明示的に再PREPAREする。片側だけ続行したり古い音を繰り返したりしない。EOFは初版では残りを0埋めして停止する運用とし、サンプル単位で正確な有限長終了は別拡張とする。

## 資源方針と実装順

1. RC1の保存済み入力を別buildで再現し、同じP4/R2・SDCで基準値を取得する。承認済み成果物を上書きしない。
2. 固定4096 byte、共通ステレオ制御、追加BSRAMなしで所有権と要求ゲートを実装する。制御状態は数十～百数十bit程度を設計上の目安とするが、CSR・token・エラー経路を含むLUT/CLS増分は合成前に断定しない。
3. 境界判定を登録し、既存next_okに相当する待機段で整合させる。仲裁の組合せ経路へ広い比較を追加しない。STOPと応答、公開と境界が同時発生した場合の優先順位を明示する。
4. 配置後CLS ≤4320、追加BSRAM 0、Setup ≥+0.100 ns、Setup/Hold違反0を確認する。RC1比の余裕減少とRecovery/Removalも報告する。収まらない場合は機能を増やさず状態・CSR共有を再検討する。
5. 既存キャッシュflushのまま描画同時転送を測る。改善が必要と判明した場合だけch別キャッシュなどを別差分で比較する。範囲付きflushや大きなFIFOを最初から追加しない。

## 必須検証

- 連番PCMでA/B境界と複数周回の欠落・重複・左右ずれを検出する。
- 最終byteの未応答中に補充許可が出ないこと、未公開半面へ要求しないことをassertする。
- 公開重複、古い世代、片側未完了、Host転送失敗、長いポーリング遅延、token折返し条件を検証する。
- STOP/reset/再PREPAREと遅延応答・timeout・公開が競合しても旧データや旧所有権が復活しないことを確認する。
- 補充不足時の両ch無音化と明示的再開、mono、従来PCM再生の回帰を行う。
- Queue8のWRITE完了・エラー回収と公開順序、CS異常注入の既存回帰を通す。
- 実機はメガデモ150秒・全8シーンで補充時間最大値、最小残り時間、PCM fault、左右音声欠落を測る。その後、供給遅延注入と長時間周回を行う。

今回の成果はRC1固定入力の調査と方式・予算・判定条件の整理。RTL実装、合成/P&R、ストリーミング実測は未実施であり、省資源で収容できるかの最終判定は配置結果に依存する。
