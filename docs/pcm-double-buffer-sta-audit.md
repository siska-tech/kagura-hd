# Queue8とダブルバッファPCMの設計監査

PSRAMの連続領域を同じ長さのA/Bに分け、各PCMチャネルがA→B→Aをループする案を次の試作候補とする。START/END/LOOPを最初に設定し、両半面を充填してからPREPAREとAUDIO_COMMITで開始する。現行のPREPAREは実行中のチャネルを停止して先読みを再初期化するため、半面ごとに呼ぶと連続性を保証できない。左右に使う2チャネルにはそれぞれA/Bを確保する。

## 所有権と期限

`kagura_pcm_prefetch.sv`はメモリ要求の受理時にfetch_addrを進め、応答が成功した時にデータをFIFOへ格納する。公開PCM_STATUSは再生状態やsticky faultを伝えるが、どの半面を再充填してよいかは示さない。ホストの経過時間やfetch_addrの折返しだけで上書きを始める方式は棄却する。

候補では、最終バイトの要求にチャネルと半面終端を付随させ、応答成功・FIFO格納時にその半面をホストへ返す。各半面の再利用には、ホストが全書込みの完了タグ・エラーを回収した後に発行するready通知を必要とする。先読みが次の半面に入る前にreadyを確認し、未充填なら読出しを抑止する。FIFO枯渇は既存のunderrunとして報告する。通知は世代付きで保持し、ホストのポーリング遅延でA→B→Aを見失うことを防ぐ。STOP・再PREPARE・resetで旧世代の通知と遅延応答を無効化する。ステレオ一組のready公開は両側の書込み完了後とする。

符号付き8 bit PCM、48 kHzを例にすると、4,096 byte/半面/チャネルの音声長は85.33 ms、ステレオのデータ量は96,000 byte/s、4半面で16 KiBになる。実際の補充期限は先読みが次の半面を要求する時刻。平均帯域だけでは判定できず、描画との競合・ACK待ち・ホスト転送を含む最悪補充時間を測る必要がある。

## STA判断

基準のQueue8はSetup +0.050 ns、採用基準 +0.100 ns、CLS 4,246/4,320。最悪経路はmemory_ctrlの状態からTX保持FFで、PCM二重化による直接の短縮は見込めない。サンプル本体は外部PSRAMに置き、既存の先読みFIFOを再利用する。終端判定を登録し、所有権とreadyはsystem54内で管理する。境界比較をPSRAM要求・仲裁の組合せ経路へ直結すると、その経路が新しいSTA制約になる。

`kagura_fb_core.sv`は成功したホスト書込みごとにPCM読出しキャッシュをflushする。連続補充ではキャッシュヒット率を落とし得る。まず現行flushのまま計測する。書込み範囲との重複判定には比較器と進行中の読出しへの無効化処理が要るため、これを今回のSTA改善量には算入しない。

比較は同じQueue8・place=4・route=2・SDCで行う。機能判定は連番サンプルの左右一致、半面末尾の未応答読出し、周回、補充遅延、古いready、STOP/reset、メモリエラーを含める。配置後のCLS、Setup/Hold違反数、Recovery/Removalを基準版と照合する。実機判定はメガデモ150秒の全8シーンでPCM fault・左右欠落・補充期限超過を記録する。

本監査の成果は方式選定と検証条件。新規RTLの実装、配置配線、ストリーミング実測は今後の検証項目である。
